**Version:** 1.0

**Development Timeline:** 1-week MVP + iterative enhancements

## 1. Executive Summary

**Product Name:** ViaProto  
**Tagline:** Personalized Learning Journeys Made Simple

**One-Liner:** ViaProto is a web application that generates AI-powered, personalized learning roadmaps with curated external resources, progress tracking, and team collaboration features.

**Core Value Proposition:** Self-directed learners get structured, comprehensive learning paths without spending hours researching resources. We curate and organize; we don't replace content creators.

**Target Launch:** 7-day MVP with authentication, payments, and core path generation

---

## 2. Product Overview

### 2.1 Problem Statement

Self-directed learners struggle to create structured, comprehensive learning paths when exploring new topics. They waste hours researching "where to start," evaluating resource quality, and determining proper sequencing. Common pain points:

1. Missing foundational knowledge due to poor sequencing
2. Overwhelmed by too many resource options
3. Lack of accountability and progress tracking
4. Abandoning learning goals due to poor structure

Traditional course platforms offer rigid curricula; free resources are scattered and unorganized.

### 2.2 Target Users

**Primary (60% focus):** Self-directed adult learners (25-45 years old, $50K-150K annual income) seeking career advancement or personal development

**Secondary (25% focus):** Small development teams and startups (2-10 people) coordinating team learning and upskilling

**Tertiary (10% focus):** College students and recent graduates (18-25) supplementing formal education

**Quaternary (5% focus):** Hobbyists and retirees exploring new interests

### 2.3 Solution Overview

An AI-powered web application that generates personalized, step-by-step learning pathways by:

1. **Accepting user input:** Topic selection from pre-defined categories + skill level (beginner/intermediate/advanced)
2. **Generating structured paths:** AI researches and compiles comprehensive roadmaps with sequenced sections, curated resources, time estimates
3. **Tracking progress:** Authenticated users track completed resources, add notes, monitor completion
4. **Enabling collaboration:** Team accounts share path libraries and track team member progress
5. **Maintaining ethics:** All resources link to original sources; no content replication or AI-generated instruction

## 3. Core Features & Requirements

### 3.1 Topic Selection System

**3.1.1 Topic Database**
- Pre-defined topic hierarchy to minimize prompt injection risk
- Topics organized by categories and tags
- Synonym mapping for common variations (e.g., "React" = "React.js" = "ReactJS")
- Typeahead search functionality
- Browse by category interface

**3.1.2 Topic Generation & Curation**
- Initial topic list generated by AI and manually reviewed
- Iterative generation until comprehensive coverage achieved
- Target: 500+ topics across major learning domains at launch
- Post-launch: Community suggestions for new topics (admin approval required)

**3.1.3 Input Fields**
- Topic selection (typeahead or browse)
- Skill level: Beginner / Intermediate / Advanced
- Optional: Time availability (hours per week)
- Optional: Specific learning goals (freeform text, max 500 chars)

### 3.2 Learning Path Generation

**3.2.1 AI Models by Tier**
- **Free Tier:** DeepSeek v3 or equivalent low-cost model (~$0.0085 per path)
- **Pro/Team Tier:** Claude Sonnet 4.5 (~$0.105 per path with research)
- All tiers use web search for current, real resources

**3.2.2 Path Structure** (Option 2: Modular Sections with Annotations)

```
Learning Path
├── Metadata (title, topic, skill level, total estimated hours)
├── Section 1
│   ├── Order: 1
│   ├── Title & Description
│   ├── Prerequisite Level: required | recommended | optional
│   ├── Notes: (freeform text for guidance)
│   ├── Estimated Hours
│   └── Resources (ordered list)
│       ├── Resource 1.1 (title, URL, type, free/paid, estimated minutes)
│       ├── Resource 1.2
│       └── ...
├── Section 2
│   └── ...
└── Section N
```

**3.2.3 Resource Requirements**
- All resources must link to external sources (no content replication)
- Resource types: video, article, book, project, audio, graphic
- Each resource includes:
  - Title
  - Direct URL to original source
  - Type classification
  - Free/Paid/Unknown indicator
  - Brief description (1-2 sentences)
  - Estimated time to complete (minutes)
- Free alternatives always provided when paid resources recommended
- Link preview generation for credibility (catches broken links)

**3.2.4 Generation Prompting Strategy**
- Emphasize finding real, current resources via web search
- Include explicit instruction to mark free vs. paid resources
- Request estimated time commitments
- Enforce structured output format (JSON schema)
- Include validation step for URL format correctness

**3.2.5 Link Validation (Post-MVP)**
- Link preview generation catches broken links at display time
- Broken links trigger UI notification: "This resource is unavailable. Regenerate this section?"
- Pro/Team tier: Optional automated link validation pass with Claude Sonnet 4.5
- Fallback resources automatically suggested when primary link fails

### 3.3 Path Visibility & Sharing

**3.3.1 Free Tier Paths**
- All free tier-generated paths are **public by default**
- Indexed and searchable by all users
- Free users can view any public path
- Free users cannot track progress (even on public paths)

**3.3.2 Pro/Team Tier Paths**
- **Private by default**
- Owner can toggle path to public
- Private paths only visible to:
  - Path creator
  - Team members (if in team account)
- Public paths appear in browse/search for all users

**3.3.3 Path Browsing**
- Browse public paths by category/topic
- Sort by: Recently created, Most popular, Estimated time
- Filter by: Skill level, Topic category
- Search by keyword

### 3.4 Progress Tracking

**3.4.1 MVP (Week 1) - Conditional Launch**
- Path saving: All authenticated users can save generated paths
- Progress tracking: **Nice-to-have for MVP** (fast-follow if time permits)
- If progress tracking makes MVP:
  - Pro/Team users can check off completed resources
  - Progress persists across sessions
  - Completion percentage calculated per section and overall path
- If progress tracking doesn't make MVP:
  - All users can view paths
  - Progress tracking becomes Week 2 priority

**3.4.2 Post-MVP (Week 2+)**
- Resource-level completion tracking (checkboxes)
- Time spent logging (optional user input)
- Personal notes per resource (markdown support)
- Section completion percentage
- Overall path completion percentage
- "Last active" timestamp for each path
- Progress history/activity log

**3.4.3 Free Tier Restrictions**
- Cannot track progress on any path (free or paid tiers)
- View-only access to all public paths
- Must upgrade to Pro for progress tracking

### 3.5 Generation Rate Limits

**3.5.1 Limit Structure**
- **Free:** 1 path generation per billing cycle
- **Pro:** 10 path generations per billing cycle
- **Team:** 10 path generations per seat per billing cycle

**3.5.2 Limit Enforcement**
- Limits reset on billing cycle (not calendar month)
- Unused generations do not roll over
- After hitting limit:
  - User can continue using existing paths
  - "Generate" button disabled with upgrade prompt
  - Clear messaging: "You've used X of Y paths this month. Upgrade for more."

**3.5.3 UI Indicators (Post-MVP)**
- Badge showing "X/Y paths remaining this month"
- Warning at 80% usage: "You have 2 path generations remaining"
- Upgrade CTA when limit reached

### 3.6 Team Features

**3.6.1 MVP Team Functionality**
- Data model supports teams from Day 1 (even if UI is limited)
- Team account types: Owner, Admin, Member
- Shared path library (all team members can view team paths)
- Basic RBAC:
  - **Owner:** Billing access, add/remove members, full admin privileges
  - **Admin:** Create/edit team paths, assign paths to members
  - **Member:** View team paths, track individual progress

**3.6.2 Team UI (Fast-Follow, Days 8-14)**
- Team creation/invitation flow
- Team path library view
- Member management interface
- Team member progress dashboard (admins only)

**3.6.3 Post-MVP Team Features (Weeks 3-4)**
- Required path assignments
- Team progress analytics
- Email notifications for assignments
- Team-wide learning goals/milestones

## 4. Technical Architecture

### 4.1 Technology Stack

**4.1.1 Foundation**
- **Boilerplate:** ShipFast (Next.js) + daisyUI - $169-299 one-time
- **Framework:** Next.js 14+ (React)
- **Language:** TypeScript
- **Styling:** Tailwind CSS + daisyUI components

**4.1.2 Backend & Infrastructure**
- **API:** Next.js API routes (serverless functions)
- **Database:** Self-hosted Supabase (PostgreSQL) via Coolify
- **Authentication:** Supabase Auth (Google, GitHub social logins)
- **Payments:** Stripe (included in ShipFast)
- **LLM API:** OpenRouter (Claude Sonnet 4.5, DeepSeek v3)
- **Hosting:** Hetzner VPS via Coolify orchestration
- **Object Storage:** Scaleway (exports, user content)
- **CDN:** Bunny CDN (static assets)

**4.1.3 Key Libraries**
- React Query (data fetching/caching)
- Zod (validation)
- Zustand or React Context (state management)
- Sharp (image optimization)
- Resend or Nodemailer (transactional emails)

**4.1.4 Additional Resources**
- **Logo:** LogoFast
- **Analytics:** DataFast
- **Illustrations:** Undraw (SVG)
- **Backgrounds:** Hero Patterns (SVG)
- **Icons:** Heroicons or Lucide
- **Blobs:** Haikei (SVG)
- **Doodles:** Figma Doodles

### 4.2 Data Models

**4.2.1 Users Table** (Supabase Auth)
```typescript
User {
  id: uuid (primary key)
  email: string
  name: string
  avatar_url: string
  created_at: timestamp
  subscription_tier: enum('free', 'pro', 'team')
  subscription_status: enum('active', 'canceled', 'past_due')
  stripe_customer_id: string
  stripe_subscription_id: string
  team_id: uuid (foreign key, nullable)
  team_role: enum('owner', 'admin', 'member', null)
  paths_generated_this_cycle: int (default: 0)
  cycle_start_date: timestamp
}
```

**4.2.2 Teams Table**
```typescript
Team {
  id: uuid (primary key)
  name: string
  created_at: timestamp
  owner_id: uuid (foreign key -> Users)
  stripe_customer_id: string
  stripe_subscription_id: string
  seat_count: int
  subscription_status: enum('active', 'canceled', 'past_due')
}
```

**4.2.3 Learning Paths Table**
```typescript
LearningPath {
  id: uuid (primary key)
  creator_id: uuid (foreign key -> Users)
  team_id: uuid (foreign key -> Teams, nullable)
  title: string
  topic: string (from pre-defined list)
  skill_level: enum('beginner', 'intermediate', 'advanced')
  description: text
  total_estimated_hours: float
  is_public: boolean (default: false for pro/team, true for free)
  model_used: string (e.g., "claude-sonnet-4-5", "deepseek-v3")
  created_at: timestamp
  updated_at: timestamp
  view_count: int (default: 0)
  generation_metadata: jsonb (prompt used, generation time, etc.)
}
```

**4.2.4 Sections Table**
```typescript
Section {
  id: uuid (primary key)
  learning_path_id: uuid (foreign key -> LearningPaths)
  order: int
  title: string
  description: text
  prerequisite_level: enum('required', 'recommended', 'optional')
  notes: text (nullable, guidance like "Return after Section 5")
  estimated_hours: float
  created_at: timestamp
}
```

**4.2.5 Resources Table**
```typescript
Resource {
  id: uuid (primary key)
  section_id: uuid (foreign key -> Sections)
  order: int
  title: string
  url: string
  type: enum('video', 'article', 'book', 'project', 'audio', 'graphic')
  is_free: boolean (nullable: null = unknown)
  description: text
  estimated_minutes: int (nullable)
  link_status: enum('active', 'broken', 'unchecked') (default: 'unchecked')
  last_checked_at: timestamp (nullable)
  created_at: timestamp
}
```

**4.2.6 Progress Table** (Post-MVP)
```typescript
Progress {
  id: uuid (primary key)
  user_id: uuid (foreign key -> Users)
  resource_id: uuid (foreign key -> Resources)
  completed: boolean (default: false)
  completed_at: timestamp (nullable)
  time_spent_minutes: int (nullable)
  notes: text (nullable, markdown supported)
  created_at: timestamp
  updated_at: timestamp
  
  UNIQUE(user_id, resource_id)
}
```

**4.2.7 Topics Table** (Pre-defined topics)
```typescript
Topic {
  id: uuid (primary key)
  name: string
  slug: string (unique, URL-friendly)
  synonyms: string[] (array of alternative names)
  category: string (e.g., "Programming", "Design", "Business")
  tags: string[] (array)
  description: text
  is_active: boolean (default: true)
  created_at: timestamp
}
```

**4.2.8 Data Model Notes**
- Design supports migration to Option 3 (Dependency Graph) by adding:
  - `prerequisites: uuid[]` to Sections table
  - Circular dependency validation logic
- Row-Level Security (RLS) policies via Supabase:
  - Users can only read their own progress
  - Users can only edit paths they created (unless team admin)
  - Public paths readable by all
  - Team members can access team paths

### 4.3 API Architecture

**4.3.1 Core API Routes**

```
/api/topics
  GET /search?q=react          # Typeahead search
  GET /categories              # List all categories
  GET /:slug                   # Get topic details

/api/paths
  POST /generate               # Generate new learning path
  GET /                        # List user's paths (or public paths)
  GET /:id                     # Get specific path with sections/resources
  PATCH /:id                   # Update path (title, visibility)
  DELETE /:id                  # Delete path
  GET /public                  # Browse public paths
  POST /:id/regenerate-section # Regenerate specific section (post-MVP)

/api/progress (Post-MVP)
  GET /paths/:pathId           # Get user's progress for a path
  POST /resources/:resourceId  # Mark resource complete/incomplete
  PATCH /resources/:resourceId # Update notes, time spent

/api/teams (Fast-Follow)
  POST /                       # Create team
  GET /:teamId                 # Get team details
  POST /:teamId/invite         # Invite team member
  DELETE /:teamId/members/:userId # Remove member
  GET /:teamId/paths           # List team paths
  GET /:teamId/progress        # Team progress dashboard (admin only)

/api/stripe
  POST /create-checkout        # Create Stripe checkout session
  POST /webhook                # Stripe webhook handler (included in ShipFast)
  POST /create-portal          # Customer portal (manage subscription)
```

**4.3.2 OpenRouter Integration**

```typescript
// Generation endpoint pseudo-code
POST /api/paths/generate
{
  topic: string,
  skill_level: string,
  goals?: string
}

→ Determine user's tier & model to use
→ Check generation limit (paths_generated_this_cycle)
→ If limit exceeded: return 429 with upgrade message
→ Call OpenRouter API:
    - Free tier: deepseek-v3 with web search
    - Pro/Team: claude-sonnet-4-5 with web search
→ Parse structured JSON response
→ Validate URLs, resource types
→ Store in database (LearningPath + Sections + Resources)
→ Increment paths_generated_this_cycle
→ Return path ID and full data
```

**4.3.3 OpenRouter Prompt Template** (Simplified)

```
You are an expert curriculum designer creating a personalized learning path.

TOPIC: {topic}
SKILL LEVEL: {skill_level}
USER GOALS: {goals}

REQUIREMENTS:
1. Research current, high-quality resources using web search

   - Title and description

   - Optional notes for guidance (e.g., "Return here after Section 5")
   - 3-7 resources with REAL, VERIFIABLE URLs
   - Estimated hours to complete section

4. For each resource, specify:
   - Title
   - Direct URL to original source (not a search results page)
   - Type (video/article/book/project/audio/graphic)
   - Whether it's FREE, PAID, or UNKNOWN
   - Brief description (1-2 sentences)
   - Estimated minutes to complete

5. CRITICAL: Always provide free alternatives when recommending paid resources
6. CRITICAL: Only link to real resources you've verified via search

OUTPUT FORMAT: JSON matching this schema:
{
  "title": "Learning Path Title",
  "description": "Overall path description",
  "total_estimated_hours": 40,
  "sections": [
    {
      "order": 1,
      "title": "Section Title",
      "description": "What this section covers",
      "prerequisite_level": "required",
      "notes": "Optional guidance text",
      "estimated_hours": 8,
      "resources": [
        {
          "order": 1,
          "title": "Resource Title",
          "url": "https://...",
          "type": "article",
          "is_free": true,
          "description": "Brief description",
          "estimated_minutes": 30
        }
      ]
    }
  ]
}
```

### 4.4 UI Components (daisyUI)

**4.4.1 Component Mapping**
- `card` - Learning path cards, section containers, resource listings
- `badge` - Free/paid indicators, skill levels, resource types, tags
- `progress` - Completion tracking bars (overall path, per section)

- Leverage existing daisyUI components (don't build custom)
- Use daisyUI themes for consistent styling
- Mobile-first responsive design
- Skeleton loaders during generation/fetching

## 5. User Flows

### 5.1 New User Flow (Free Tier)

1. **Landing Page**
   - Value proposition, feature overview, pricing
   - CTA: "Generate Your First Learning Path" or "Browse Public Paths"
   
2. **Topic Selection** (No Auth Required Yet)
   - Typeahead search or browse categories
   - Select skill level (beginner/intermediate/advanced)
   - Optional: Add learning goals (500 chars max)
   - Click "Generate Path"

3. **Authentication Gate**
   - Modal appears: "Sign up to generate your learning path"
   - Google/GitHub sign-in via Supabase Auth
   - After auth: Path generation begins automatically

4. **Path Generation**
   - Loading screen (30-60 seconds)
   - "Researching resources for [topic]..."
   - "Building your personalized roadmap..."

5. **Path Display**
   - Full learning path with expandable sections
   - Resource cards with type badges, free/paid indicators
   - Estimated time commitments
   - Link previews (if available)
   - "Save Path" button → saves to user's library
   - "You've used 1 of 1 free paths this month. Upgrade for more."

6. **Browse Public Paths**
   - View other users' public paths
   - Filter by topic, skill level
   - View-only (no progress tracking)

### 5.2 Pro User Flow

1. **After Upgrading via Stripe**
   - Redirected to dashboard
   - "You now have 10 path generations per month with premium AI"

2. **Path Generation**
   - Same flow as free tier, but uses Claude Sonnet 4.5
   - Potentially higher-quality, more comprehensive paths

3. **Progress Tracking** (Post-MVP)
   - Check off completed resources
   - Add notes to resources
   - View completion percentage
   - "Last studied: 2 days ago"

4. **Path Management**
   - Make paths public/private (toggle)
   - Export to PDF/Markdown (post-MVP)
   - Edit path title/description
   - Delete paths

### 5.3 Team User Flow

1. **Team Creation**
   - Team owner creates team during checkout
   - Invites members via email
   - Members receive invitation link

2. **Team Member Experience**
   - Access "Team Paths" tab
   - View all team-shared paths
   - Track individual progress on team paths
   - Generate personal paths (within their 10/month limit)

3. **Team Admin Experience**
   - Create paths for the team
   - View team member progress dashboard
   - Assign required paths (post-MVP)
   - Manage team members

## 6. Pricing & Monetization

### 6.1 Pricing Tiers

**Free Tier ($0/month)**
- 1 learning path generation per billing cycle (DeepSeek v3)
- All generated paths are public
- Browse all public paths (view-only)
- No progress tracking
- No path exports

**Pro Tier ($12-15/month or $120-144/year with 20% discount)**
- 10 learning path generations per billing cycle (Claude Sonnet 4.5)
- Private paths by default (can make public)
- Full progress tracking with notes and time logging
- Export paths to PDF/Markdown (post-MVP)
- Access to premium path templates (post-MVP)
- Priority support

**Team Tier ($10/seat/month or $100/seat/year with 17% discount)**
- Minimum 2 seats required
- All Pro features per seat (10 paths/month per member)
- Shared team path library
- Individual progress tracking per team member
- Team admin dashboard with analytics
- Ability to assign required learning paths
- Example: 5-person team = $50/month or $500/year

### 6.2 Payment Integration

**Stripe Setup** (Included in ShipFast)
- Three subscription products: Free, Pro, Team
- Monthly and annual billing options
- Webhook handlers for:
  - `checkout.session.completed` → activate subscription
  - `customer.subscription.updated` → update tier
  - `customer.subscription.deleted` → downgrade to free
  - `invoice.payment_failed` → handle failed payments

**Billing Cycle Logic**
- Rate limits reset on subscription anniversary date (not calendar month)
- First month may be partial (prorated if mid-month signup)
- Track `cycle_start_date` in User table
- Cron job resets `paths_generated_this_cycle` at cycle start

**Customer Portal**
- Stripe Customer Portal for subscription management
- Users can upgrade/downgrade, update payment methods, view invoices

### 6.3 Unit Economics

**Cost Structure:**
- **Variable Costs (per user/month):**
  - Free tier: ~$0.01 (DeepSeek v3)
  - Pro tier: ~$1.05 (Claude Sonnet 4.5, 10 paths)
  - Team tier: ~$1.05 per seat
  
- **Fixed Costs (monthly):**
  - Hetzner VPS: ~€20-50 ($22-55)
  - Scaleway object storage: ~€5-15 ($5-16)
  - Bunny CDN: ~€5-10 ($5-11)
  - Domain + email: ~$1.25/month
  - Stripe fees: 2.9% + $0.30 per transaction
  - **Total fixed:** ~$35-85/month

**Gross Margins:**
- Pro tier: 91-93% (after LLM costs)
- Team tier: 89-90% (after LLM costs)

**Break-Even:**
- ~50-60 paying customers to cover fixed costs
- At 100 paying customers: ~$1,200-1,500 MRR, ~$110-150 LLM costs
- At 500 paying customers: ~$6,000-7,500 MRR, ~$525-750 LLM costs

## 10. Risk Mitigation & Considerations

### 10.1 Technical Risks

**LLM API Reliability:**
- **Risk:** OpenRouter or model downtime
- **Mitigation:** Graceful error handling, retry logic, fallback to alternative models

**Link Rot:**
- **Risk:** External resources go offline over time
- **Mitigation:** Link preview generation catches broken links at view time, encourage regeneration

**Database Scaling:**
- **Risk:** Performance degradation as data grows
- **Mitigation:** Proper indexing, query optimization, consider read replicas if needed

**Cost Overruns:**
- **Risk:** Unexpected LLM API costs if usage spikes
- **Mitigation:** Strict rate limiting, usage monitoring, alerts at 80% of budget threshold

### 10.2 Product Risks

**Low Free-to-Paid Conversion:**
- **Risk:** Users don't see value in upgrading
- **Mitigation:** Showcase Pro benefits clearly, limit free tier strategically, A/B test pricing/limits

**Content Quality:**
- **Risk:** AI generates low-quality or irrelevant resources
- **Mitigation:** Use premium models (Claude Sonnet) for paid tiers, prompt engineering, manual review of sample paths

**Prompt Injection:**
- **Risk:** Users try to manipulate AI with malicious prompts
- **Mitigation:** Pre-defined topic list (no free-text), input sanitization, prompt engineering safeguards

### 10.3 Business Risks

**Competitive Pressure:**
- **Risk:** Established players (Coursera, Udemy) add similar features
- **Mitigation:** Focus on niche (personalized curation, team collaboration), build community, iterate quickly

**Regulatory/Legal:**
- **Risk:** Copyright concerns for linking to resources
- **Mitigation:** Only link to publicly available resources, terms of service disclaimers, DMCA takedown process

**Churn:**
- **Risk:** Users generate 10 paths in month 1, then cancel
- **Mitigation:** Focus on ongoing value (progress tracking, path updates), annual billing incentives

## 12. Glossary

**Learning Path:** A structured sequence of sections and resources designed to teach a specific topic from a defined skill level.

**Section:** A logical grouping of related resources within a learning path, with a defined order and prerequisite level.

**Resource:** An external link to instructional content (video, article, book, etc.) with metadata about type, cost, and estimated time.

**Prerequisite Level:** Classification of how essential a section is (required, recommended, optional) to completing the learning path.

**Path Generation:** The process of using AI to research and compile a structured learning path based on user input.

**Progress Tracking:** Recording which resources a user has completed within a learning path.

**Public Path:** A learning path visible to all users, including those on the free tier.

**Private Path:** A learning path visible only to the creator and (if applicable) their team members.

**Rate Limit:** The maximum number of learning paths a user can generate within a billing cycle based on their subscription tier.

**Billing Cycle:** The recurring period (monthly or annual) during which subscription benefits and rate limits apply.
